An audio file has two distinct areas: the compressed audio stream and the tag data. Raza Music operates exclusively on the tags. The audio itself is never decoded, processed, or re-encoded during a metadata save.

This means there is no generation loss, no recompression, and no risk of corrupting the sound quality of the track.

How saving works

Changes you make in Raza Music are queued in memory as you work. They are not written to disk automatically. To save, choose Save Metadata from the Library menu on Mac. You can cancel at any time, and tracks without pending changes are never touched.

  • 1You make changes — fix a title, correct an artist, tag an album
  • 2Changes are held in the local database until you are ready
  • 3You choose Save Metadata from the Library menu
  • 4Raza Music reads the existing tags, merges your changes, and writes the updated file atomically to disk
  • 5Only files with pending changes are modified — everything else is untouched

What gets written

Raza Music writes to the tag format native to each file, so the result stays compatible with any other music app.

What is never changed

Raza Music uses merge semantics — it reads all existing tag data first, then only updates the specific fields you changed. Everything else is preserved exactly as it was.

  • The compressed audio stream itself
  • Chapter and bookmark data in M4B audiobooks
  • File timestamps (creation and modification dates on disk)
  • All tag fields not managed by Raza Music
